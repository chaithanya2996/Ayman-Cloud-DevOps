Commands for DevOps Engineer:
----------------------------------

clear       -> clear the screen
ctrl + L    -> clear the screen

pwd         -> print working directory/ present working directory

sudo su -   -> we will switch to root user.
sudo -i     -> we will switch to root user.
sudo -s     -> we will switch to root user.

1. sudo su -
sudo su -
What happens?
sudo executes the su command as root.
su - switches to the root user.
The - (hyphen) means login shell.

This loads:

Root's environment
Root's PATH
Root's .bash_profile
Root's .profile
Root's .bashrc

Example:

$ whoami
azureuser

$ sudo su -

# whoami
root

Check current directory:

pwd

Output

/root

Check PATH

echo $PATH

You'll see root's PATH.

Without "-"
sudo su

You become root without loading the login environment.

Current directory remains your directory.

Example

/home/azureuser
2. sudo -i
sudo -i

This is the preferred method.

It means:

"Run an interactive login shell as root."

It behaves almost exactly like:

sudo su -

It loads

Root environment
Root PATH
Root profile
Home directory becomes
/root

Example

$ sudo -i

# whoami
root

# pwd
/root
Why is it preferred?

Because:

Simpler
Doesn't require su
Recommended in the sudo documentation
Uses only sudo
3. sudo -s
sudo -s

This is different.

It starts a shell as root, but does not create a login shell.

That means:

Current environment is mostly preserved.

Example

$ pwd
/home/azureuser

$ sudo -s

# pwd
/home/azureuser

Notice:

You are root

root

But you're still in

/home/azureuser

It also keeps many environment variables.

Example

echo $HOME

May still show

/home/azureuser

depending on the system configuration.

Difference in Environment

Suppose your user has

export JAVA_HOME=/opt/java17
sudo -s

Usually keeps

JAVA_HOME=/opt/java17
sudo -i

Starts fresh.

JAVA_HOME

may not exist unless root has it configured.

| Command     | Recommendation       | Reason                                                       |
| ----------- | -------------------- | ------------------------------------------------------------ |
| `sudo -i`   | ⭐ Best choice        | Officially recommended, clean root login shell               |
| `sudo su -` | Good                 | Works similarly to `sudo -i`, but unnecessarily invokes `su` |
| `sudo -s`   | Good for quick tasks | Keeps your current environment and working directory         |
